# Project Governance

The Developer Handbook is an open-source publication with a maintainer-led governance model. The goal is to welcome meaningful participation while preserving a coherent learning sequence and a consistently high technical standard.

## Roles

### Maintainer

The maintainer is responsible for:

- curriculum structure and editorial direction;
- technical and safety review;
- contributor moderation;
- repository and release administration;
- security response;
- final merge and release decisions.

The current maintainer is [Michael Adeniken](https://github.com/superflyad).

### Contributors

Contributors propose, research, write, review, test, or improve project material. A contributor does not need commit access. Sustained contributors may be invited to take ownership of a subject area or review function.

## Decision process

Routine corrections are decided through pull-request review. Material changes to scope, architecture, licensing, publication formats, or chapter order begin with a public issue or discussion.

Decisions prioritize:

1. technical accuracy and safe guidance;
2. durable mental models over transient tool recipes;
3. a coherent progression for readers;
4. evidence from primary authoritative sources;
5. maintainability and reproducibility;
6. accessibility and cross-platform usefulness.

The maintainer seeks consensus when practical and records consequential decisions in [DECISIONS.md](DECISIONS.md). When consensus cannot be reached, the maintainer makes the final decision and documents the reasoning.

## Releases

Minor corrections may be published continuously to the website. Tagged editions provide stable downloadable artifacts and release notes. Breaking curriculum or publication changes should be called out explicitly in the changelog.

## Changes to governance

Governance changes require a public pull request and a written rationale. Changes take effect when merged into the default branch.
